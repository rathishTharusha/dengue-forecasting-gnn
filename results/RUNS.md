# Results index

This file used to be generated by `scripts/index_runs.py` and indexed the
`results/phase*.csv` series produced by the Phase-2/3 implementation. Both the
generator and the CSVs it indexed were removed in the Phase-2/3 cleanup: EXP-015
onward rebuilt on architectures verified against the published papers, and
keeping two generations of results side by side was the confusion the cleanup
existed to remove.

To recover any of it:

```bash
git checkout phase23-archive
```

Every entry from EXP-001 to EXP-014 keeps its exact config and unrounded numbers
inline in [`../docs/EXPERIMENT_LOG.md`](../docs/EXPERIMENT_LOG.md), so those runs
remain citable without the CSVs. What the tag adds is the ability to *re-run*
them.

## Where current results live

| location | what |
|---|---|
| `analysis/results/improved_sweep.{json,csv,md}` | The five verified architectures × four increments, merged from the Kaggle sweep kernels (EXP-019) |
| `analysis/results/sweep/improved_sweep_<ARCH>.json` | Raw per-kernel output, one file per architecture |
| `analysis/results/reproduced_baseline.{json,csv}` | The same architectures plus the AAGCN adaptive switch, run locally (EXP-020) |
| `analysis/results/adaptive_graph_*.{json,csv}` | Graph-mode comparison on the controlled encoder (EXP-018, EXP-022) |
| `analysis/results/error_diagnosis.json` | Where the baseline error lives (EXP-021) |
| `analysis/results/{renewal_feasibility,physics_STGAT}.json` | Renewal-equation physics (EXP-023) |
| `analysis/results/{r_predictability,mechanistic_r}.json` | Why the physics cannot help (EXP-024) |
| `analysis/results/{outbreak_signal,response_diagnosis}.json` | Outbreak detection and model response (EXP-025) |
| `results/table_seir_validation.md` | SEIR-SEI reproduction against Phaijoo & Gurung Table 1, regenerated by `scripts/verify_seir_paper.py` |

Records are one row per `(architecture, arm, origin, seed)`. They do **not**
carry a per-horizon breakdown; where the report needs one, it has to be re-run.
