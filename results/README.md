# Results

Committed metric tables and figures. **These are the artifacts the report cites** — a number
that exists only inside a notebook's output cell cannot be checked, diffed, or re-plotted.

## Where results live

Current results are written under `analysis/results/`, one JSON per job plus a
merged table where several jobs combine. `results/` itself now holds only this
index, [`RUNS.md`](RUNS.md), and `table_seir_validation.md` — the SEIR-SEI
reproduction against Phaijoo & Gurung, regenerated by
`scripts/verify_seir_paper.py`. See [`RUNS.md`](RUNS.md) for the full map.

Records carry one row per `(architecture, arm, origin, seed)` and are **not**
pre-aggregated, so anyone can recompute mean ± sd, run a paired test, or drop a
seed without a re-run. They do not carry a per-horizon breakdown; a report that
needs one has to re-run the job.

Every fold is scored twice — `RMSE` over all windows and `RMSE_clean` with the
six week-395 artifact windows excluded — for models and for the persistence floor
alike. A number quoted without saying which column it came from is ambiguous by
about 15 RMSE.

## Rule

Anything committed here must have a matching entry in [`../docs/EXPERIMENT_LOG.md`](../docs/EXPERIMENT_LOG.md)
with the config and commit SHA that produced it. No orphan numbers.
