# Data provenance — re-download by hand, and verify

Two rules govern every input to the SEIR-GNN experiments:

1. **Legitimate and re-obtainable.** Every number comes from an official or
   peer-reviewed source that anyone can download again. Nothing is generated by
   us: no interpolation, no projection, no filled gaps.
2. **No future information.** A forecast made at the start of week *i* uses only
   what was published before week *i* began. This holds even where a future
   value correlates strongly. `analysis/lib/corrected_data.py` enforces it and
   `tests/test_no_future_leakage.py` proves it.

Raw downloads go in `data/raw/`, which is git-ignored. Checksums for the static
files are in `data/external/source_manifest.csv`.

```bash
python analysis/_build/source_manifest.py --check
```

## 1. Weekly dengue cases — Epidemiology Unit, Ministry of Health

| | |
|---|---|
| **Official source** | Weekly Epidemiological Report (WER), Table 1 "Selected notifiable diseases reported by Medical Officers of Health", Dengue row **A** (cases this week) |
| **Index page** | https://www.epid.gov.lk/weekly-epidemiological-report |
| **File pattern** | `https://www.epid.gov.lk/storage/post/pdfs/<file>`, e.g. [vol_48_no_27-english.pdf](https://www.epid.gov.lk/storage/post/pdfs/vol_48_no_27-english.pdf) |
| **Machine-readable table used** | `datasets/output_Dengue Fever.csv` (parsed from those PDFs; in the shared Drive) |
| **Verification** | `verify_case_source.py --all` downloads the official PDF for every report and compares printed row A district by district. **Result (2026-09-14): all 553 source files match exactly, 14,341 of 14,341 division values.** Results: `analysis/results/source_verification/wer_all_verification.json` (with each PDF's SHA-256) |

Notes from the full check:
- Three January 2024 reports (Vol 51 No 02–04) were re-uploaded by the Epidemiology
  Unit under new file names; their old links return 404. The new links are in
  `REUPLOADED` in the script and in the results file.
- Table 1 appears in two layouts over the years (diseases as rows, or turned 90°
  with divisions as rows). The script detects the layout from the table's
  structure, never from agreement with the data.
- In 16 reports the printed national cumulative total (row B) does not equal the sum
  of the printed divisions. That is an inconsistency inside the PDFs; the district
  values, which are what we use, match.

**Manual check (5 minutes):**
1. Open any report from the index page, e.g. Vol 44 No 34 (2017).
2. Find Table 1 and the Dengue Fever block. Row A is the line below the one
   labelled with the disease name.
3. Compare with the rows for that source file in `output_Dengue Fever.csv`.

**Transformations applied by us** — each one reproducible, none generating a value:
- **Ordering** by report volume and number: Volume N = year 1973 + N.
- **District names** follow the authors' `Configs/disease_config.json`.
  *Kalmunai* (a separate health division inside Ampara) is excluded, as in the
  original benchmark.
- **One correction:** Vol 48 No 02 (26 Dec 2020 – 01 Jan 2021) prints a row A
  that is a spreadsheet formula error (15 of 24 cells equal the sum of the two
  before them). The same table's row B (year to date, which equals the weekly
  count in week 1) is used instead. Both rows and the evidence are in
  `data/external/report_corrections.json`.
- **Missing reports are left missing (NaN).** 7 weeks have no report in the
  source. They are never filled; any forecast window touching one is dropped.

## 2. District population — Department of Census and Statistics (DCS)

| Figure | Official source | Manual download |
|---|---|---|
| 2012 Census count per district | DCS district reports, Table A1 | `http://www.statistics.gov.lk/pophousat/cph2011/Pages/Activities/Reports/District/<Name>.pdf` (DCS spellings `Baticaloa`, `Monaragala`; Anuradhapura, Monaragala and Polonnaruwa use `.../District/<Name>/A1.pdf`) |
| National census total 20,359,439 | DCS "Census of Population and Housing 2012 – Key Findings", p. 19 | https://srilanka.unfpa.org/sites/default/files/pub-pdf/Census-2012.pdf |
| Mid-year estimates 2014–2024 | DCS / Registrar General's Department | https://www.statistics.gov.lk/Resource/en/Population/Vital_Statistics/Mid-year_population_by_district_and_sex_2024.pdf |

**Checks built in:** each census district total equals male + female on the same
line, and the 25 districts sum **exactly** to 20,359,439. The mid-year table's
districts sum to the national figure every year.

**No future information:** weeks in year *Y* use the official figure for an
**earlier** year. 2013–14 use the 2012 census; year *Y* ≥ 2015 uses the DCS
estimate for *Y*−1. Which figure each year used is listed in
`data/corrected/rebuilt_population_sources.csv`.

**Not used:** the HDX workbook's WFP/OCHA *projections* (modelled, not counted),
and its GN-level population sums, which fall 93,076 short of the official
census. HDX is used only for the **over-60 share**, a ratio.

## 3. Climate — ERA5 reanalysis

| | |
|---|---|
| **Official source** | ECMWF/Copernicus ERA5 ([Hersbach et al. 2023](https://doi.org/10.24381/cds.adbb2d47)) |
| **How obtained** | Open-Meteo historical API, no account: https://open-meteo.com/en/docs/historical-weather-api |
| **Manual download** | Paste the URL below into a browser (Colombo's point); the other districts' coordinates are in `data/raw/era5_openmeteo/points.json`. For an independent path, the Copernicus Climate Data Store gives the same ERA5 data with a free account. |
| **Committed table** | `data/external/era5_weekly_by_district.csv` |

```
https://archive-api.open-meteo.com/v1/archive?latitude=6.8688&longitude=80.02&start_date=2013-01-01&end_date=2024-03-31&daily=temperature_2m_mean,temperature_2m_min,temperature_2m_max,precipitation_sum,relative_humidity_2m_mean,soil_moisture_0_to_7cm_mean&models=era5&timezone=Asia%2FColombo
```

**What is ours:** a single interior point per GADM district polygon (a sample,
not an area average), aggregated to 7-day means from each report week's start.

**No future information:** a forecast for weeks *i*… may read climate **up to
week *i*−2**. ERA5 is released about 5 days after the fact, so week *i*−1 is not
complete when the forecast is made.

## 4. Vegetation — MODIS NDVI

| | |
|---|---|
| **Official source** | NASA MOD13Q1 v061, 250 m, 16-day composite ([Didan 2021](https://doi.org/10.5067/MODIS/MOD13Q1.061)) |
| **How obtained** | ORNL DAAC MODIS/VIIRS subset web service, no account: https://modis.ornl.gov/data/modis_webservice.html |
| **Manual download** | Open in a browser, e.g. `https://modis.ornl.gov/rst/api/v1/MOD13Q1/subset?latitude=6.8688&longitude=80.02&band=250m_16_days_NDVI&startDate=A2021001&endDate=A2021017&kmAboveBelow=5&kmLeftRight=5`. The ORNL [Global Subset Tool](https://modis.ornl.gov/globalsubset/) does the same through a form. |
| **Committed tables** | `data/external/modis_ndvi_composites_by_district.csv` (every composite), `..._weekly_by_district.csv` |

**What is ours:** a ±5 km box around each district's interior point, averaging
valid pixels.

**No future information:** each week takes the **latest composite that was
already available before the week began**. That means the 16-day window has
ended, plus an assumed 16-day release delay. Nothing is interpolated.

## 5. Epidemiological parameters

| Parameter | Source | Use |
|---|---|---|
| Intrinsic incubation 5.9 d (3.4–10) | [Chan & Johansson 2012](https://doi.org/10.1371/journal.pone.0050972) | model constant |
| Extrinsic incubation 15 d at 25 °C, 6.5 d at 30 °C | same | SEIR-SEI arm only |
| Infectious period 2–7 d | WHO via [Yi et al. 2021](https://doi.org/10.1109/ACCESS.2021.3129997) | model constant / sensitivity |
| Seroprevalence, Colombo children 2008–09: 51.4% | [PLoS NTD 2013](https://doi.org/10.1371/journal.pntd.0002259) | **prior for initial immunity** (pre-period) |
| Seroprevalence, suburban Colombo 2013–14: adults 90.8%, children 50.7% | [PLoS ONE 2015](https://doi.org/10.1371/journal.pone.0144799) | prior for initial immunity (sampled at the series start) |
| Seroprevalence, 9 districts × 3 age groups, 2022–23 | Jeewandara et al., [medRxiv](https://www.medrxiv.org/content/10.1101/2023.04.23.23288986v1) / [J Med Virol 2024](https://doi.org/10.1002/jmv.29394), Table 1 | **validation only** (collected after the study period) |
| Serotype switches (DENV-2 2016–17, DENV-3 late 2019) | [EID 2020](https://doi.org/10.3201/eid2604.190435), [PLoS NTD 2021](https://doi.org/10.1371/journal.pntd.0009624) | **oracle arm only** (known in hindsight) |
| Under-reporting evidence, 2.5×–30× | several (see `seir_parameters.json`) | sensitivity range, never a fixed constant |

**Seroprevalence manual check:** open the medRxiv full text, find Table 1, and
compare with `data/external/seroprevalence_nine_districts.csv`. Every row sums
to its all-ages count and every column to the table's total. The source is
itself inconsistent in two places (Jaffna 31.3% stated vs 36.1% implied by its
age groups; Trincomalee 54.3% vs 56.5%); both are recorded, not corrected.

## 7. Mobility — Google COVID-19 Community Mobility Reports

| | |
|---|---|
| **Official source** | https://www.google.com/covid19/mobility/ (archive) |
| **Files used** | `https://www.gstatic.com/covid19/mobility/{2020,2021,2022}_LK_Region_Mobility_Report.csv` |
| **Coverage** | daily, 2020-02-15 to 2022-10-15, six place categories, percent change from a pre-pandemic baseline |
| **Granularity** | **national only** — Google published no sub-region rows for Sri Lanka, so every district carries the same value. It can explain national timing, never spatial differences |
| **Licence** | free to use with attribution |
| **Available in real time?** | Yes, published with a few days' lag |

**Why these two are here.** The largest single loss in the frozen 9-origin
protocol is the window 2019-11 to 2020-06, where national cases collapse from
3057 to 299 a week while the model over-predicts with a bias of +19.8 (EXP-035,
EXP-036). The collapse is not epidemiological. In the weekly table the turn is
unmistakable: 2020-03-07 carries stringency 12 and 462 cases; 2020-03-14 carries
stringency 68, workplace mobility −33%, and 245 cases; by 2020-04-04, stringency
100 and 79 cases.

**Weeks outside the coverage are left `NaN`, never zero-filled** (rule R3). A
model may choose to treat pre-2020 stringency as 0 on the grounds that such
policies did not exist, but that is a modelling decision and stays in the model.

**Manual check (2 minutes):** open the OxCGRT file, find the `LKA` row, and
compare any date with the `stringency_index` column of
`data/external/covid_response_weekly.csv` for the week containing it. The weekly
value is the mean of that week's days, and `stringency_days` records how many
days were available.

## What is excluded, and why

| Excluded | Reason |
|---|---|
| All climate channels of `sri_lanka_2013-2022_shifted.npy` | On a different timeline from the cases; channels 6–10 hold values 12–17 weeks in the future (`docs/ARRAY_AUDIT.md`, findings 2, 6, 7). `features.load_multivariate` now refuses them. |
| Interpolated case weeks | Generated values that borrow the following week |
| Interpolated NDVI | Generated values that read the next composite |
| WFP/OCHA population projections | Modelled, not counted |
| Same-year population estimates | Published after the year |
| 2022–23 seroprevalence as an input | Collected after the period it would initialise |
| Serotype-switch dates as an input | Known only in hindsight |

## Earlier results affected

- **Every benchmark on the original array** trained on 2023 data (rows 0–47),
  later than every test period. Re-run on corrected data:
  `corrected-benchmark-*` kernels.
- **The covariate sweep** (`covariates-a3tgcn`, `covariates-stgat`) and the
  climate analyses in EXP-024 used misaligned, future-shifted channels. **They
  are not valid evidence about climate** and should not be cited.
